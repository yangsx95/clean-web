模块由三个文件组成清晰的三层结构：
- `main.rs`：仅承担 Windows 提权前置逻辑（Release 构建下通过 advapi32/kernel32/shell32 FFI 检测 UAC 并 `runas` 重启），随后委托给库函数；macOS/其他平台直接跳过。
- `lib.rs`：定义 `cleanweb_lib::run()` 作为真正的 Tauri 入口，使用 `tauri::Builder` 完成三件事——setup 阶段创建数据目录、注入 `storage::AppState`、在 macOS 上安装登录代理并阻止窗口关闭；通过 `tauri::generate_handler![]` 集中注册 storage / subscription_download / mihomo / access_logs 四大业务域的所有 IPC 命令；另起后台线程每 750ms 轮询同步访问日志。
- `platform.rs`：以 `#[cfg(target_os = ...)]` 分支提供 OS 专属实现，对外暴露统一 API（`os_version`、`detect_network_conflicts`、`pid_running`、`terminate_process`、`kill_process`、`start_mihomo_privileged`、`install_login_agent`）；macOS 路径通过 `/usr/bin/osascript` 请求管理员权限执行 shell 脚本，将 mihomo 二进制安装到 `/Library/Application Support/CleanWeb` 并以 root 启动，同时写入 LaunchAgent plist 实现开机自启；Windows 路径保持最小化“fail-open”行为，冲突检测返回空集。
依赖方向单向：`main.rs → lib.rs → {storage,subscription_download,mihomo,access_logs,platform}`，`platform.rs` 不反向依赖任何业务模块。
