第一批：平台无关纯逻辑（可在当前 Windows 开发机上 `cargo test` + `npm test` 验证，零返工）

目标：在不动 macOS 真机验证的前提下，补齐三类与平台无关的业务缺口，同时让 crate 在 Windows 上首次能编译通过测试。所有新增系统级代码（特权服务、TUN 真机验证、签名）留到后续批次，在 Mac 上做。

──────────────────────────
步骤 0：最小平台抽象层（前置，为让 Windows 能编译/测试）
──────────────────────────
新建 `src-tauri/src/platform.rs`，把所有 OS 专属调用收口到这个模块，按 `cfg(target_os)` 分流：
- `os_version()`：macOS 调 `sw_vers`；Windows 读 `HKLM\...\CurrentVersion`（用 std + reg 读取，避免新依赖，失败回退 `env::consts::OS`）
- `detect_network_conflicts()`：macOS 走 `route -n get default` + `scutil --nc list`（现有逻辑搬过来）；Windows 走 `route print` / `Get-NetAdapter` 风格检测，或先返回空（标注为 Windows 占位，后续批次补 WFP/TUN 检测）
- 进程信号：`pid_running` / `libc::kill(SIGTERM/SIGKILL)` 仅在 `cfg(unix)` 下编译；Windows 分支仅依赖 `child.kill()`（已跨平台）+ PID 文件清理，PID 恢复路径在 Windows 标注为暂不支持（与 fail-open 一致）
重构 `mihomo.rs` 和 `access_logs.rs` 改调 `platform::` 函数，删除内联的系统命令。
验收：`cargo build` 和 `cargo test` 在 Windows 上通过；macOS 分支保持原有行为（在 Mac 上复测，不在本机验证）。

步骤 1：补齐安全搜索（safe-search）
──────────────────────────
扩展 `mihomo.rs::safe_search_hosts()`（当前只有 Google/Bing/DuckDuckGo/YouTube 共 8 条）：
- Yahoo：搜索结果由 Bing 后端驱动，映射 `search.yahoo.com` → `strict.bing.com`（best-effort）
- Yandex：映射到其 family 变体（若存在公开 DNS 重定向端点），否则记录为"仅浏览器级"
- Baidu / Sogou / 360：经核实这三个引擎**不提供**官方强制安全搜索的 DNS 重定向端点（其安全搜索依赖 cookie/账户）。对它们不伪造一个假域名，而是采用"反向守卫"：当安全搜索开启时，阻断这些引擎的已知不安全变体域名（如对应的无限制搜索入口），并在 spec/UI 文案中如实标注此限制。这符合 product-spec "如实描述能力、不过度承诺"的要求。
新增纯函数 + 单元测试验证 `safe_search_hosts()` 输出包含每个引擎的条目，并测试启用/关闭分类开关时的行为。

步骤 2：URI-list 代理节点标准化导入（核心缺口）
──────────────────────────
现状：`subscription_download.rs::parse_proxy_payload()` 对 base64/明文 URI-list **只计数不转换**；`mihomo.rs::build_config()` 只处理 `format=="clash"` 的载荷。结果是 URI-list 订阅导入后节点不会出现在生成的配置里。
新增 `src-tauri/src/proxy_uri.rs`，实现纯函数：
- `parse_uri_list_to_clash_proxies(text: &str) -> (Vec<Value>, Vec<IgnoredUri>)`
- 支持协议：`ss://`、`ssr://`、`vmess://`（base64 JSON）、`vless://`、`trojan://`、`hysteria2://`/`hy2://`、`tuic://`、`wireguard://`、`socks://`、`http(s)://`
- 每条 URI 按 Mihomo 官方 YAML schema 转成一条 proxy mapping；解析失败的进 `IgnoredUri`（保留行号 + 原因），不静默丢弃
- 严格只产出 `proxies` 字段，不带任何 DNS/TUN/rule/script（与现有净化策略一致）
改 `parse_proxy_payload`：URI-list 分支调用上述函数，把结果包装成 `{"proxies":[...]}` 的 Clash 载荷再加密存储，`detected_format` 仍记为 `clash`（因为已标准化为 Clash），并在 `RefreshReport` 里反映真实节点数。
充分单测：每种协议一条合法 + 一条非法 URI，断言产出的 proxy 字段正确、非法行进 ignored。
